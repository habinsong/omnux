# 기술 스택

[한국어](./기술스택_정리.md) · [English](./en/tech-stack.md)

업데이트 기준: 2026-09-12

역할별로 작은 런타임을 나눠 붙였다. 각 런타임이 무엇을 맡고 무엇을 맡지 않는지 적는다.

| 영역 | 기술 | 이유 |
|---|---|---|
| 코어 런타임 | .NET 9 (`PublishAot=true`) | metrics, guarded kill, WebSocket/HTTP, 텔레그램, 파일 상태, provider 라우팅, 도메인 오케스트레이션 |
| 데스크톱 셸 | Rust + TypeScript + React (Tauri v2 + React 19 + TypeScript + Tailwind CSS v4) | 앱 셸(Rust)과 UI(React), Zustand 상태관리, react-markdown 렌더링 |
| 데스크톱 빌드 | Vite 7 + `@tailwindcss/vite` | 빠른 HMR, Tailwind v4 통합 빌드 |
| 데스크톱 UI | Tailwind CSS v4, lucide-react | 3-tier 토큰(Light/Glass/Dark), 반응형 접이식 도구 화면 |
| 실행기 | Python | 코드 실행과 검증 |
| 테스트·스크립트 | Node.js, npm scripts | 저장소 위생, 계약 검사, 프런트 문법 확인 |
| 상태 | JSON, Markdown, SQLite FTS | 사람이 읽을 수 있는 운영 상태와 기록 |

## 언어 책임 경계

- Rust는 앱 셸(Window 관리)만 맡고, provider·API·상태·도메인 로직을 소유하지 않는다.
- TypeScript와 React는 데스크톱 UI에만 쓴다. 비즈니스 로직은 .NET 미들웨어가 전담한다.
- JavaScript는 계약 검사와 Playwright 브라우저 실행 리소스에 쓴다.
- Python은 샌드박스 실행과 코드 검증에만 쓴다.
- Node.js는 테스트·계약 검사와 Playwright 브라우저 실행 어댑터에 쓴다. 프로세스 수명과 도구 권한은 .NET이 소유한다.
- 새 비즈니스 로직과 상태 오케스트레이션은 기본적으로 .NET 9 미들웨어가 전담한다.

## 원본 위치 경계

- .NET 9 런타임, 비즈니스 로직, 정책 코드는 `apps/omnux-middleware/src/`에만 둔다.
- 데스크톱 셸의 React/TypeScript 코드는 `apps/desktop/src/`에 두고, Rust 셸 코드는 `apps/desktop/src-tauri/src/`에 둔다.
- Python 코드는 `apps/omnux-sandbox/executor.py`에만 둔다.
- Node.js 계약 검사와 러너 코드는 `scripts/`에 둔다.
- 루트에는 Electron/Codex 번들 산출물인 `main.js`, `preload.js`, `worker.js`를 보관하지 않는다.
- 미들웨어 루트에는 코딩 스모크가 생성한 `main.py`, `main.js`, `main.c` 같은 작업 산출물을 보관하지 않는다.
- 새 코드를 만들 때는 위 경계를 넘기지 않는다.

## 새 언어/런타임 승인 기준

- 새 언어, 런타임, 프레임워크, 번들러는 기본 거부한다. 현재 스택으로 요구사항을 만족할 수 없거나 플랫폼이 공식적으로 요구할 때만 예외를 검토한다.
- 승인하려면 같은 변경 안에 이 문서, 영문 문서, `scripts/check-tech-stack-contract.mjs` 계약 검사를 함께 갱신한다.
- 승인 기록에는 책임자, canonical source home, 상태 파일 위치, secret 취급 방식, 빌드/검증 명령, 제거/rollback 계획을 적는다.
- 새 런타임은 비즈니스 로직, provider 라우팅, 상태 오케스트레이션을 `.NET 9` 미들웨어 밖으로 옮기는 명분이 될 수 없다.
- 실험/스파이크 산출물은 `workspace/`에만 두고, 제품 코드로 승격하기 전까지 `apps/`나 저장소 루트에 보관하지 않는다.

## Phase 5 스택 유입 차단 게이트

- Phase 5 화면 이식은 기존 `apps/desktop/` Tauri/Vite/React/TypeScript 셸만 사용한다. 레거시 정적 대시보드(`apps/omnux-dashboard/`)는 삭제됐다.
- Phase 5 변경 전후에는 `npm test`를 통과시킨다. 범위를 줄여 확인할 때도 최소 `node scripts/check-tech-stack-contract.mjs`와 `node scripts/check-repo-hygiene.mjs`를 함께 실행한다.
- 새 루트 앱 디렉터리, 새 source home, 새 번들러, 새 package manager, 새 runtime shortcut은 새 언어/런타임 승인 기준을 통과하기 전까지 만들지 않는다.
- 기존 루트 `omnux/` 프로토타입은 활성 source home이 아니다. 삭제 또는 이관을 확정하기 전까지 파일 목록을 동결하고, 새 런타임/패키지/빌드 산출물을 추가하지 않는다.

## 브랜드와 호환 alias 경계

- 제품명, 패키지명, 런처, 상태 디렉터리, 새 사용자 노출 문구의 canonical 이름은 `omnux`다.
- 이전 브랜드명은 역사 문맥이나 마이그레이션 예시에만 남길 수 있다.
- 구 접두사 기반 루트 alias, Electron/Codex legacy alias, 새 런타임 shortcut은 다시 만들지 않는다.
- 호환 alias가 필요하면 임시 shim으로만 추가하고, 제거 조건과 계약 검사를 같은 변경에 남긴다.
- 데스크톱/README/package metadata의 새 제품 표기는 `omnux`를 사용한다.

## 프런트엔드 원칙

데스크톱 앱은 도구형 화면이다. 정보 밀도, 반복 사용, 좁은 폭 입력을 우선한다. 대화, 실행 결과, 설정, 로그가 빨리 보이도록 구성한다.

- Tailwind CSS v4 토큰을 쓴다. 기능별 CSS는 해당 화면 범위로 한정하고 CSS-in-JS나 새 디자인 시스템은 도입하지 않는다.
- `window.alert`, `window.confirm`, `window.prompt` 대신 커스텀 Dialog를 쓴다.
- `dangerouslySetInnerHTML` 대신 `react-markdown`으로 렌더링한다.
- 인라인 스타일 대신 Tailwind 클래스를 쓴다.
- 3-tier 테마(Light/Glass/Dark)를 지원하고, 기본은 Light 모드다.

`scripts/check-ui-slop.mjs`가 그라데이션, hover scale, 글래스 효과, 대문자 트래킹, 마케팅 형용사, 부정 대구를 검사한다.

## 브라우저 실행 리소스 (2026-09-07)

- 기존 BrowserTool의 Node/Playwright 스크립트를 `apps/omnux-middleware/resources/browser/`의 `PlaywrightHost.cjs`, `A2UiRenderer.cjs`로 분리해 어셈블리에 포함한다. 이 두 파일만 브라우저 실행 리소스로 허용한다.
- .NET 원본은 `apps/omnux-middleware/src/`에 유지한다. `Infrastructure/Browser`가 실행·오류·프로세스 종료를 소유하고, 스크립트는 브라우저 페이지와 선언형 UI를 다룬다.
- 브라우저 상태는 해당 프로세스의 새 임시 컨텍스트에 둔다. 사용자 브라우저 프로필이나 OAuth·API 자격증명 파일을 읽지 않는다.
- Node.js와 Playwright 패키지, Playwright Chromium(`omnux setup`이 설치) 또는 Chrome이 필요하다. 데스크톱 패키지에 이 의존성이 포함되는지는 별도 패키징 검증 대상이다.
- 검증: `npm test`, `node scripts/check-gateway-runtime-contract.mjs --explore-only`. 기능 제거 시 두 embedded resource와 Browser/Canvas 연결·런타임 검사를 함께 제거한다.
