# 자동화

자동화 화면은 `apps/desktop/src/features/automation-workspace/`에 있다.
기존 자동화 화면·마법사·상태 저장소는 제거했다. 전송은 기존 WebSocket 게이트웨이를 사용한다.

## 사용 흐름

1. **새 자동화**에서 할 일과 반복 주기·시간을 입력한다. 매일·매주·매월을 지원한다.
2. 이름·시간대·실행 방식·재시도·Telegram 알림은 **이름과 추가 설정**에서 정한다.
3. **자동화 저장**은 예약만 저장한다. 첫 실행은 다음 예약 시각이며, 즉시 실행은 별도 버튼이다.
4. 자동화를 선택하면 최근 실행 결과를 읽는다. 이전 실행·원본 기록·삭제는 접힌 영역에 있다.
5. **예약 끄기**는 다음 예약과 대기 중인 실행을 막는다. 이미 시작한 실행을 취소하는 기능은 아니다.

선택한 주기·시간은 요청 문장의 시간 표현보다 우선한다(`scheduleSourceMode=manual`).
다음 예약과 실행 기록 시각은 해당 자동화의 시간대에 맞춰 표시한다.
편집 실패·화면 이동·재연결 때 작성한 내용을 유지한다. 저장하거나 취소하기 전에는 다른 자동화를 선택하지 않는다.
Telegram 알림은 새 자동화에서 기본으로 꺼져 있다. 결과를 수동으로 보내는 동작은 대상 확인을 거친다.

## 실행과 결과

- 웹 검색·링크 읽기는 Gemini 연결, 코드 생성은 Groq 연결, 브라우저 조작은 Codex 연결이 필요하다.
- 예약 저장 자체는 웹 검색이나 브라우저 실행을 시작하지 않는다. 코드 방식의 저장에는 코드 생성이 포함된다.
- 스케줄러는 같은 자동화를 대기열에 중복 등록하지 않고 실행 직전 켜짐 상태·예약 시각을 다시 확인한다.
- 실행 완료마다 고유한 결과 파일을 남긴다. 같은 시각에 끝난 실행이 과거 파일을 덮어쓰지 않는다.
- 코드의 표준 출력·오류 출력은 자동화 표시 단계에서 잘라내지 않는다. 파일 저장 실패는 실행 오류로 보고한다.
- `routine_run_detail`의 `output`은 사용자 결과, `content`는 메타데이터를 포함한 원본 기록이다.
- 자동화 WebSocket 응답은 요청의 `requestId`를 돌려준다. 이전 결과가 늦게 도착해도 현재 선택을 덮어쓰지 않는다.
- 자동화 목록은 `running`과 `nextRunAtMs`를 포함한다. 화면은 예약 활성화와 현재 실행을 구분한다.

상태 파일은 `OMNUX_ROUTINE_STATE_PATH`, 실행 결과 루트는 `OMNUX_ROUTINE_RUNS_DIR`로 지정할 수 있다.
기본값은 각각 상태 루트의 `routines.json`, 작업 루트의 `routines/`이다.

## 검증

- `npm test`: 소스 경계·단위 테스트·격리 HTTP/WS·샌드박스 검사.
- `npm --prefix apps/desktop run build`: 타입 검사와 프런트엔드 빌드.
- `scripts/check-automation-workspace-ui.mjs`: Playwright 브라우저 시나리오. 개발 서버와
  `check-gateway-runtime-contract.mjs`가 만든 `output/playwright/grok-gateway-fixtures.json`을 사용한다.

브라우저 응답은 모의 처리하며, 실제 서버 검사는 임시 상태·작업 폴더와 비활성 API 설정에서 수행한다.
로컬 Python 실행·예약 CRUD·키 부재 실패를 검증한다. 실제 모델의 결과 품질·OAuth 로그인 성공은 검증하지 않는다.
