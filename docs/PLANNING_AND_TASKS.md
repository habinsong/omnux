# 자동화 / 계획 / Task Graph

[한국어](./PLANNING_AND_TASKS.md) · [English](./en/planning-and-tasks.md)

업데이트 기준: 2026-09-07

작업 화면에서는 만들고 싶은 결과를 적고 계획을 확인한 뒤 실행한다.

## 화면 구조

- **계획 만들기**: 필요한 결과를 적는다. 조건과 계획 방식은 펼쳐서 입력한다.
- **이 계획으로 실행**: 내용을 확인한 뒤 누르면 계획 승인과 실행을 순서대로 처리한다. 추가 검토와 단계 편집은 보조 영역에서 선택한다.
- **작업 중단 / 남은 작업 이어가기**: 실행 중에는 작업 전체를 중단할 수 있고, 중단 후에는 미완료 단계부터 이어간다.
- **결과**: 파일과 프로그램 출력을 먼저 보여준다. 이전 실행과 자세한 로그는 필요할 때 펼친다.
- **저장된 작업**: 목록을 펼쳐 기존 작업을 선택한다. 현재 실행의 세부 단계와 설정도 기본적으로 접혀 있다.

## 저장 위치

| 위치 | 내용 |
|---|---|
| `~/.omnux/plans/` | plan, review, execution 상태 |
| `~/.omnux/tasks/` | task graph 원본 |
| `workspace/.runtime/tasks/<graph>/<task>/attempts/<id>/` | 실행 차수별 stdout/stderr/result.json |
| `~/.omnux/routing-policy.json` | 라우팅 override |

계획 생성과 리뷰는 LLM을 사용하고, task graph 생성은 승인된 plan을 규칙 기반으로 분해한다.

## 실행 복구

- 재시도는 선택한 단계와 그 후속 단계를 다시 대기 상태로 바꾼다. 후속 검증이 완료됐더라도 다시 실행하며, 실행 중인 후속 단계가 있으면 먼저 중단해야 한다.
- 이어서 실행은 완료된 단계를 유지하고 나머지 단계를 재개한다. 재시도와 이어서 실행도 원본 계획의 승인을 확인한다.
- 코딩 대화 ID는 실행 도중부터 기록한다. 중단 후 재시도에서도 같은 작업 폴더를 사용한다.
- 처음부터 실행은 새 코딩 문맥을 사용한다. 이전 실행 기록과 로그는 보존한다.
- `task_output_get`은 기본적으로 최신 출력을 반환한다. `timestamp` 또는 `ts`에 실행 시작 시각의 Unix 밀리초 값을 넣으면 해당 차수의 출력을 조회한다.
- 예전 형식의 실행 경로도 저장된 `TaskExecutionRecord`를 통해 읽는다.
