# 계획과 Task Graph

[한국어](./PLANNING_AND_TASKS.md) · [English](./en/planning-and-tasks.md)

업데이트 기준: 2026-09-12

**작업** 화면에서 만들고 싶은 결과를 적고, 계획을 확인한 뒤 실행한다. 탭은 목록 · 새 계획 · 계획 · 실행 · 결과이고, 뒤 세 개는 해당 상태가 있을 때만 나타난다.

## 화면 구조

| 버튼 | 하는 일 |
|---|---|
| 계획 만들기 | 필요한 결과를 적는다. 조건과 계획 방식은 펼쳐서 입력한다 |
| 이 계획으로 실행 | 계획 승인과 실행을 순서대로 처리한다. 추가 검토와 단계 편집은 보조 영역에 있다 |
| 작업 중단 | 실행 중인 작업 전체를 멈춘다 |
| 남은 작업 이어가기 | 멈춘 뒤 미완료 단계부터 이어간다 |
| 저장된 작업 | 목록을 펼쳐 기존 작업을 고른다 |

결과 영역은 파일과 프로그램 출력을 먼저 보여 준다. 이전 실행과 자세한 로그는 필요할 때 펼친다.

## 저장 위치

| 위치 | 내용 |
|---|---|
| `~/.omnux/plans/` | plan, review, execution 상태 |
| `~/.omnux/tasks/` | task graph 원본 |
| `workspace/.runtime/tasks/<graph>/<task>/attempts/<id>/` | 실행 차수별 stdout, stderr, result.json |
| `~/.omnux/routing-policy.json` | 라우팅 override |

계획 생성과 리뷰는 LLM을 쓴다. task graph는 승인된 plan을 규칙 기반으로 나눈다.

## 실행 복구

- 재시도는 선택한 단계와 그 후속 단계를 다시 대기 상태로 바꾼다. 실행 중인 후속 단계가 있으면 먼저 멈춰야 한다.
- 이어서 실행은 완료된 단계를 유지하고 나머지를 재개한다. 재시도와 이어서 실행도 원본 계획의 승인을 확인한다.
- 코딩 대화 ID는 실행 도중부터 기록한다. 멈춘 뒤 재시도해도 같은 작업 폴더를 쓴다.
- 처음부터 실행은 새 코딩 문맥을 쓴다. 이전 실행 기록과 로그는 보존한다.
- `task_output_get`은 기본으로 최신 출력을 돌려준다. `timestamp`나 `ts`에 실행 시작 시각(Unix 밀리초)을 넣으면 그 차수의 출력을 조회한다.
