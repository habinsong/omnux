# 빌드

빌드 화면은 `apps/desktop/src/features/build-workspace/`에서 새로 작성했다.
이전 BuildPage·build-store·보조 UI 모듈은 제거했다. 홈과 사이드바의 화면은 유지하면서 새 상태 처리로 연결했다.

## 기본 흐름

1. 만들거나 바꾸고 싶은 내용을 적고 **만들기**를 누른다. 파일 첨부·끌어놓기·붙여넣기를 지원한다.
2. 진행 중에는 실제 서버의 진행 메시지와 **작업 중단**을 표시한다. 다음 요청을 미리 적을 수 있다.
3. 결과의 요약·파일·프로그램 출력을 읽는다. 파일을 누르면 내용을 읽고, HTML은 **미리 보기**로 연다.
4. **다시 실행하기**에서 프로그램 입력을 전달하고 선택한 결과를 실행한다.
5. 중단된 작업은 **중단한 요청 이어 쓰기**로 원래 요청·모델·작업 문맥을 복원한다.

모델·언어·프로젝트 이름은 **모델과 작업 설정**, 스킬·노트는 **스킬과 참고 노트**에서 설정한다.
함께 작업하기·결과 비교하기에서는 사용할 보조 모델을 직접 선택한다. `none` 선택을 그대로 전송한다.
첨부는 최대 6개, 전체 10MB다. 전송·읽기 실패가 이전 결과나 작성한 요청을 지우지 않는다.
Cmd/Ctrl+Enter로 요청을 보낼 수 있으며 한글 조합 중에는 전송하지 않는다.

**저장한 빌드**에서 이전 기록을 다시 연다. 열어 둔 빌드의 이름·프로젝트 이름을 바꾸거나 기록을 삭제할 수 있다.
다른 기록을 선택하기 전에는 현재 작성 중인 요청을 보내거나 새 빌드에서 비운다.
홈에서 작업 방식을 바꿔 시작하면 새 빌드 문맥을 사용한다. 같은 방식의 후속 요청은 열린 빌드에 연결한다.

## 실행 계약

- 생성·진행·중단·파일 실행·대화 목록·대화 조회·이름 수정·삭제 응답을 요청 ID로 연결한다.
- `coding_execute_result` 요청의 선택적 `target`은 `main` 또는 `worker-N`이다.
  생략하면 기존 자동 대상 선택을 유지한다. 존재하지 않는 대상은 다른 결과로 대체하지 않고 거부한다.
- 실행 파일이 없는 계획 단계와 `(planning)` 등의 내부 표시는 셸 명령으로 실행하지 않는다.
- 재실행은 선택한 결과의 입력·작업 폴더를 사용한다. 결과는 같은 스냅샷이 아직 최신일 때 저장한다.
  실행 도중 새 결과가 생기거나 기록이 삭제되면 해당 기록을 덮어쓰지 않는다.
- 대화 조회에도 `programStdOut`·`programStdErr`를 포함해 생성 직후와 다시 열었을 때 같은 출력을 보여준다.
- 모델 이름이 같아도 대표 결과와 보조 모델 결과를 대상 번호로 구분한다. 다른 대상의 미리보기·출력을 섞지 않는다.
- 화면 안에서 처리하는 오류는 전역 팝업으로 중복 표시하지 않는다. 오류 로그는 유지한다.

아코디언은 외부 컴포넌트 소스를 복사하지 않고 직접 작성했다.
화면·스타일은 네이티브 폼·details·dialog와 기존 React 의존성으로 작성했다.

## 검증과 남은 범위

- `npm test`: 단위 테스트와 격리된 HTTP/WS·코드 실행 검사.
- `npm --prefix apps/desktop run build`: 타입 검사·배포 빌드.
- `scripts/check-build-workspace-ui.mjs`: 실제 서버 계약에서 얻은 응답 모양과 모의 브라우저 응답으로 실행하는 새 UI 검사.
  이전 화면용 `check-build-ui.mjs`는 이 검사로 대체했다.

실제 모델 호출·OAuth 로그인은 수행하지 않는다. 모의 CLI가 만든 작업 파일의 실제 Python 실행은 검사한다.
프로젝트 이름은 대화 메타데이터다. 프로젝트의 실제 폴더를 코딩 작업 폴더로 연결하는 동작은 추가 작업 대상이다.
하네스·훅·플러그인·규칙과 다른 전용 화면의 결과 연결은 전체 리뉴얼에서 계속 작업한다.
현재 재실행 응답에는 기존 24,000자 출력 제한이 남아 있으며, 전체 출력 보존은 후속 실행 계층 개선 대상이다.
