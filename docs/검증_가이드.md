# 검증 가이드

[한국어](./검증_가이드.md) · [English](./en/validation.md)

업데이트 기준: 2026-09-12

코드나 설정을 수정한 경우 다음 절차에 따라 단계별 검증을 수행합니다.

## 기본 검증

| 명령 | 기대 결과 |
|---|---|
| `npm test` | 전체 묶음 통과 (`[test] ok`) |
| `./scripts/omnux setup` | 의존성 확인·설치, 빌드, `npm test`, 실행기 등록 |
| `curl -s http://127.0.0.1:41880/readyz` | `"ready":true` |
| `dotnet run --project apps/omnux-middleware/Omnux.Middleware.csproj -- doctor --json` | 순수 JSON doctor 보고서 |

Windows 환경에서는 `.\scripts\omnux.ps1 setup`을 사용합니다.

## npm test 단계

`scripts/run-omnux-tests.mjs` 테스트 러너가 아래 단계 순으로 실행하며, 검사 실패 시 즉시 파이프라인을 중단합니다.

| 순서 | 묶음 | 스크립트 |
|---|---|---|
| 1 | 공유 카탈로그 | `apps/shared/audit-renewal.test.mjs`, `apps/shared/model-registry.test.mjs` |
| 2 | 저장소·경계 | `check-repo-hygiene`, `check-core-daemon-boundary-contract`, `check-desktop-shell-boundary-contract`, `check-security-boundaries`, `check-extension-wiring-contract` |
| 3 | 화면 모델 | `check-activity-screen`, `check-insights-screen`, `check-operations-screen`, `check-routing-screen`, `check-agents-screen`, `check-review-screen`, `check-skills-screen` |
| 4 | 워크스페이스 소스 | `check-build-workspace-source`, `check-chat-workspace-source`, `check-explore-workspace-source`, `check-automation-workspace-source`, `check-task-workspace-source`, `check-renewal-screens`, `check-ui-slop` |
| 5 | 스택·레지스트리 | `check-tech-stack-contract`, `apps/shared/generate-cs-registry.js --check` |
| 6 | 런타임 계약 | `check-coding-python-game-contract`, `check-browser-intent-contract`, `check-chat-telegram-contract` |
| 7 | .NET | 미들웨어 빌드, `apps/omnux-middleware-tests` 단위 테스트 |
| 8 | 게이트웨이 | `check-gateway-runtime-contract` (격리 미들웨어 + Playwright Chromium) |
| 9 | 샌드박스 | `apps/omnux-sandbox/executor.py` smoke |

화면 모델 검사는 `.ts` 파일을 직접 로드합니다. 네이티브 TypeScript 실행을 지원하지 않는 환경에서는 테스트 러너가 `scripts/typescript-loader.mjs`를 자동 연결합니다.

`check-ui-slop`은 그라데이션, hover scale, 글래스 효과, 과도한 트래킹, 마케팅 수식어, 부정 대구 등 불필요한 UI 슬롭 요소를 정적 분석하며, 위반 패턴 감지 시 빌드를 차단합니다.

## 데스크톱 검증

```bash
npm run build --prefix apps/desktop
omnux
```

`omnux`는 Vite(1420)와 Tauri 셸을 띄우고, 셸이 .NET 미들웨어(41880)를 함께 실행합니다.

## 화면 검사 (Playwright)

`npm test`를 사전 실행해 게이트웨이 픽스처를 준비한 뒤, Vite 서버가 `127.0.0.1:1420`에서 응답할 때 실행합니다. `omnux` 명령으로 통합 기동하거나 `OMNUX_DESKTOP_UI_HOST=127.0.0.1 npm run dev --prefix apps/desktop`으로 Vite 단독 기동할 수 있습니다. (macOS 환경에서 `localhost` 기본 해석이 IPv6로 바인딩되는 문제를 방지하기 위해 `127.0.0.1`을 명시합니다.)

| 스크립트 | 검사 내용 |
|---|---|
| `run-workspace-ui-checks.mjs` | 질문·빌드·자동화·탐색·작업 화면 흐름 순차 검증 |
| `check-desktop-launch.mjs` | 초기 기동 및 재실행 안정성 |
| `check-viewport-fit.mjs` | 1440·768·390·320 해상도 반응형 레이아웃 맞춤 |
| `check-provider-model-defaults.mjs` | 모델 기본값 설정 정합성 |
| `audit-all-screens.mjs` | 전체 화면 가로 스크롤 넘침(overflow) 점검 및 스냅샷 |

스크린샷과 로그는 `output/playwright/` 아래에 저장됩니다.

UI 검사 스크립트는 화면의 한글 라벨 텍스트를 계약 검사로 엄격히 비교합니다. 라벨 문구를 수정할 경우 해당 검사 스크립트도 함께 갱신해야 합니다.

## 실제 연동 검증

로컬 자동화 테스트로 대체할 수 없는 외부 연동 항목입니다. 유효한 인증 토큰과 테스트 계정이 필요합니다.

| 명령 | 필요한 것 |
|---|---|
| `node scripts/telegram-mobile-live-qa.mjs --timeout-sec 180` | 봇 토큰, chat id, 모바일 텔레그램 클라이언트 |
| `node scripts/gist-bridge-remote-qa.mjs --token <GITHUB_TOKEN>` | GitHub 토큰, 외부 원격 머신 |
